# Progress Notes — Lapor Handri (per 11 Agustus 2026)

Catatan ini untuk melanjutkan pekerjaan di sesi berikutnya. Baca ini dulu sebelum lanjut.

## Status Ringkas
Aplikasi sudah bertransformasi dari SPA React murni (localStorage) menjadi full-stack dengan backend Express + SQLite, login Google OAuth, dan sistem RBAC 4-role dengan disposisi tiket berbasis divisi. **Belum di-deploy ke VPS** — masih development di localhost.

## Yang Sudah Selesai

### Milestone A — Backend & Migrasi dari localStorage
- Backend Express + SQLite (`better-sqlite3`) di folder `server/`
- Semua CRUD laporan pindah dari localStorage ke REST API (`server/routes/reports.ts`)
- Upload lampiran asli (bukan base64) via `multer`, disimpan di `uploads/`
- Hapus fitur QR poster (palsu, tidak scannable) — dicatat di `docs/future-qr-poster.md`
- Hapus field Program Studi (tidak diperlukan) dari seluruh alur (form, tampilan, DB)
- Field WA Hotline diubah jadi kontak publik yang dikelola via backend

### Milestone B — Login Admin via Google OAuth
- OAuth flow lengkap: `server/routes/auth.ts`, cookie sesi httpOnly (`lh_session`)
- **Bug penting yang pernah terjadi & sudah diperbaiki**: redirect URI awalnya mengarah ke port API (8787) langsung, menyebabkan cookie tidak konsisten dengan origin frontend (3000). Sudah diperbaiki: redirect URI sekarang `http://localhost:3000/api/auth/google/callback` (lewat proxy Vite), bukan langsung ke 8787. **Kalau nanti pindah environment/port, redirect URI di `.env` DAN di Google Cloud Console harus disesuaikan bersamaan.**

### RBAC-1 — Fondasi Role (Super Admin, Moderator, Pimpinan)
- Tabel `admin_users` (email, name, role, division, added_by)
- Bootstrap: akun pertama yang login otomatis jadi Super Admin (dikunci ke `SUPER_ADMIN_BOOTSTRAP_EMAIL` di `.env`)
- Middleware role: `requireRole`, `requireAdmin`, `requireModerator`, `requireActionable`, `requireSuperAdmin` (`server/middleware/requireAdmin.ts`)
- UI kelola akun admin (`src/components/AdminUserManagement.tsx`) — hanya Super Admin

### RBAC-2 — Divisi, Role Staff, Sistem Disposisi
Dipicu oleh analisa `Role.xlsx` (struktur organisasi FTI 4 tingkat: Dekan → Wakil Dekan → Kepala Divisi → Kepala Urusan/Staff).
- Taksonomi divisi + pemetaan kategori→divisi: `src/lib/divisions.ts`
- Role ke-4 ditambahkan: **STAFF** (login sendiri, hanya lihat tiket yang didisposisikan ke mereka)
- Endpoint disposisi: `PATCH /api/reports/:id/disposition` — Moderator/Super Admin assign tiket ke Staff di divisi yang sama
- Endpoint scoped listing: `GET /api/reports` sekarang filter otomatis berdasarkan role (Moderator→kategori divisinya, Staff→tiket miliknya, Super Admin/Pimpinan→semua)
- Endpoint `GET /api/admin-users/staff?division=X` — untuk dropdown pemilihan staf saat disposisi
- Direktori organisasi FTI (`src/lib/orgDirectory.ts`, sumber `Role.xlsx`) — dropdown quick-pick saat Super Admin menambah akun, otomatis isi role+divisi tersaran
- Dokumentasi alur lengkap: `docs/rbac-workflow-guide.md`
