### Perbaikan: Path Prefix untuk Subpath `/lapor/`
Sebelumnya ada 3 file di VPS yang di-patch **manual tanpa commit** (`App.tsx`, `api.ts`, `vite.config.ts`) supaya jalan di subpath `/lapor/`. Sekarang disatukan jadi mekanisme resmi:
- `src/lib/api.ts` — fungsi `apiUrl()` terpusat, semua pemanggilan API lewat sini.
- `vite.config.ts` — `base: process.env.VITE_BASE_PATH || '/'` (bukan hardcode).
- **Build production wajib pakai**: `VITE_BASE_PATH=/lapor/ npm run build`

### 🔴 Insiden Keamanan yang Ditemukan & Ditutup: SESSION_SECRET Placeholder
`.env` production masih pakai `SESSION_SECRET=change-this-to-a-long-random-string` — nilai placeholder yang sama persis dengan yang ada di `.env.example` (**publik di GitHub**). Siapapun yang tahu nilai itu bisa forge token JWT `role: SUPER_ADMIN` sendiri tanpa login Google sama sekali. **Sudah diperbaiki**: secret diganti jadi random 64-hex-char, `pm2 restart laporfti-api --update-env`, dan dikonfirmasi lewat test Incognito (sesi lama benar-benar tertolak setelah rotasi). **Tidak perlu tindakan lanjutan** untuk poin ini, sudah tuntas.

### Infrastruktur Deploy yang Baru Diketahui
- VPS: `tbe-fti` (aaPanel/BT-managed, path `/www/server/nvm`), proses dikelola **PM2** dengan nama `laporfti-api`, restart env butuh flag `--update-env` supaya PM2 tidak cache env lama (meski app ini pakai `dotenv` yang baca `.env` langsung tiap boot — tetap disarankan pakai `--update-env` untuk konsistensi).
- Reverse proxy: **Nginx** (config di `/www/server/panel/vhost/nginx/`), plus **Cloudflare** di depan domain `uii.ac.id` (sempat dicurigai jadi penyebab cache stale, ternyata bukan — sudah dikonfirmasi via test Incognito).

## 4 Rekomendasi untuk Dikerjakan Besok (urutan prioritas)

1. **Verifikasi RBAC end-to-end di production** — login sungguhan sebagai Moderator/Staff/Pimpinan (bukan cuma Super Admin), coba alur disposisi lengkap: Moderator terima laporan divisinya → disposisi ke Staff → Staff login → Staff lihat & proses tiketnya. Ini fitur besar yang baru diverifikasi logikanya di kode, belum pernah dites nyata end-to-end di production dengan akun asli selain Super Admin.
2. **Putuskan pemilik kategori "Lainnya"** — tidak ada divisi otomatis untuk kategori ini di `CATEGORY_TO_DIVISION` (`src/lib/divisions.ts`), jadi laporan kategori ini cuma kelihatan oleh Super Admin/Pimpinan, tidak pernah masuk antrian Moderator manapun.
3. **Bangun moderasi konten pra-publikasi** — kolom `moderation_status` (`PENDING`/`APPROVED`/`REJECTED`) sudah ada di skema DB `reports` tapi **belum ada endpoint approve/reject maupun UI antrian moderasi**. Laporan publik saat ini tayang langsung tanpa tahap penyaringan ini.
4. **Prioritas rendah, boleh ditunda**: UI audit log untuk tabel `admin_logins` (sekarang cuma bisa dicek lewat SQL langsung), dan kemampuan revoke sesi individual (sekarang cuma bisa logout semua admin sekaligus lewat ganti `SESSION_SECRET`, seperti yang baru dilakukan hari ini).
